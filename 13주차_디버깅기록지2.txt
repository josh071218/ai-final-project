# 13주차 디버깅 기록지 2 — 가계부 금액의 천 단위 쉼표 문제

**① 증상**

공통 버그를 수정한 뒤에도 가계부 데이터 104행 중 31행이 '숫자가 아님'으로 분류되어 분석에서 제외되었다. 실제 금액인데도 숫자로 인식되지 않는 문제가 발생하였다.

**② 최소 재현**

가계부 CSV에서 발견한 금액 `"35,366"`을 기존 코드인 `int("35,366")`으로 변환하면 `ValueError`가 발생한다.

하지만 쉼표를 제거한 `int("35366")`은 정상적으로 35366을 반환한다.

**③ 가설**

가계부 데이터의 금액에 천 단위 쉼표가 포함되어 있어, Python의 `int()` 함수가 이를 정수로 변환하지 못하기 때문이라고 예상하였다.

**④ 관찰**

실제 CSV에서 `"35,366"`, `"19,389"`, `"57,145"` 등의 값을 확인하였다.

공통 버그 수정 후 프로그램 실행 결과는 다음과 같았다.

- 원본: 104행
- 분석: 69행
- 비어 있음: 4행
- 숫자가 아님: 31행
- 범위 밖: 0행

**⑤ 수정**

`main.py`의 숫자 변환 부분을 다음과 같이 수정하였다.

수정 전:
`값 = int(원값)`

수정 후:
`값 = int(원값.replace(",", ""))`

이를 통해 금액에 포함된 쉼표를 제거한 다음 정수로 변환하도록 하였다. 기존 `except ValueError`와 경계값 검사는 유지하였다.

**⑥ 회귀 검증**

수정 후 프로그램을 다시 실행한 결과, '숫자가 아님'으로 제외되던 31행이 모두 정상적으로 분석에 포함되었다.

- 분석 행 수: 69행 → 100행
- 숫자가 아님: 31행 → 0행
- 비어 있음: 4행 → 4행
- 범위 밖: 0행 → 0행
- 전체 평균: 28,755.9원 → 30,864.8원

검산 결과 `104 - 4 = 100행`으로 전체 행 수가 일치하였다.

**추가로 확인할 점**

쉼표를 무조건 제거하는 방식은 `"3,5,366"`처럼 쉼표 위치가 잘못된 문자열도 숫자로 처리할 수 있다. 향후에는 천 단위 쉼표의 위치까지 검사하도록 개선할 수 있다.
